# WorkBuddy 协同工作流

## 标准流程

1. **口述更新**：用户说出要更新的日期与事项。
2. **规则校验**：WorkBuddy 按版本优先规则确认主版本；按休息日规则判断「休息」是否需要填写。
3. **生成变更**：修改对应月份的日志文件，保留原表六列结构。
4. **提交推送**：一次提交写明「日期 + 变更内容」，推送到本仓库。
5. **回报确认**：回复变更摘要与提交说明。

## 约定

- 村名一律写「太兴村」，原始材料中出现「泰兴」时自动更正，不必再问。
- 数据不准确、不确定的内容不臆测，先向用户确认。
- 涉及村民个人信息、土地明细的文件不放本仓库，留存本地。
- 每次提交只做一件事，便于版本回查。

## 进阶（待启用）

- 用 GitHub Actions 定期校验日志日期连续性、休息日规则落实情况。
- 用 Issue 管理村务待办，标签区分「待核实 / 办理中 / 已办结」。
